# RaiseTimeLine 機能定義書: 画像投稿

Oct 20, 2026 · @tamura

## 1. 概要と画像のルール

投稿とプロフィールのアイコンに画像を使えるようにする機能です。画像の実体は AWS S3 に置き、DB には S3 のキー(ファイルの住所)だけを保存します。

| 対象機能 | 画面 | 説明 |
| --- | --- | --- |
| F-15 画像アップロード | S-03 | 投稿フォームで画像を選び、投稿といっしょに送る |
| F-16 画像表示 | S-03, S-04, S-05 | カードでサムネイル表示し、クリックで拡大する |
| F-17 アイコン画像 | S-06 | プロフィール用の画像を 1 枚設定する(F-15 と同じアップロード処理を使い回す) |

| 項目 | ルール | エラー文言(仮) |
| --- | --- | --- |
| 枚数 | 1 投稿に最大 4 枚。アイコンは 1 枚 | 画像は 4 枚までです |
| 容量 | 1 枚 5MB まで | 画像は 1 枚 5MB 以下にしてください |
| 形式 | image/jpeg, image/png, image/webp。拡張子だけでなく中身でも確認する | JPEG、PNG、WebP の画像を選んでください |

権限: アップロードはログイン済みのユーザーのみ。投稿の画像の録覧は、その投稿を見られる人なら誰でも可能です。アイコンの変更は本人のみです。

## 2. アップロードの流れ

画像のバイト列はバックエンドを通しません。バックエンドは「この条件であれば書き込んでよい」という署名付き URL を発行するだけで、EC2 の通信量とメモリを使いません。投稿を作るときには、対象の画像が本当にあることをもう一度確認します(⑤)。

## 3. API と画像の表示

パスは仮です。署名付き URL の発行と、投稿作成時の画像確認が、この機能の API です。投稿作成のリクエストは「タイムライン・投稿」の機能定義書と、プロフィール更新は「認証」の機能定義書と同じです。

| メソッド | パス | 認証 | リクエスト | 成功 | 失敗 |
| --- | --- | --- | --- | --- | --- |
| POST | /api/images/upload-url | 必要 | purpose(post または avatar)、contentType、size(バイト) | 200 + { uploadUrl, imageKey, expiresIn } | 400 形式・容量が不正 / 401 |
| POST | /api/posts | 必要 | body, imageKeys(0〜4) | 201 + PostDto | 400 画像が無い・自分のキーではない・枚数超過 / 401 |
| PUT | /api/users/me | 必要 | avatarKey を含む | 200 + ユーザー | 400 / 401 |

**署名付き URL の発行(①)**

- contentType と size を強制する形で署名する。申告した値と違う PUT は S3 が拒否する
- imageKey はサーバーが決める(下記の形式)。ファイル名はクライアントから受け取らない
- 有効期限は 5 分(仮)

**画像の確認(⑤)**

1. imageKeys がすべて、ログイン中のユーザーの ID を含むキー(posts/{userId}/...)であることを確認する(他人の画像を自分の投稿に使わせない)
2. S3 に HEAD を送り、オブジェクトの有無・Content-Type・サイズを確認する
3. 先頭数バイトを読み、JPEG / PNG / WebP のファイル署名(マジックナンバー)と一致することを確認する

**画像の表示(F-16)**

PostDto の images\[\].url に、バックエンドが署名付き GET URL を入れて返します。ブラウザはその URL をそのまま img に入れます。有効期限は 1 時間(仮)です。URL の署名時刻を「時間単位に丸める」ことで、同じ画像には 1 時間の間同じ URL を返し、ブラウザのキャッシュが効くようにします。クリックで拡大するときも同じ URL を使います。

## 4. S3 と DB

**キーの形式**

| 用途 | キー | 例 |
| --- | --- | --- |
| 投稿の画像 | posts/{userId}/{uuid}.{ext} | posts/12/3f9a...c1.webp |
| アイコン | avatars/{userId}/{uuid}.{ext} | avatars/12/77b0...e4.png |

**DB**

- post\_images.image\_key にキーを、users.avatar\_key にアイコンのキーを保存する(URL ではなくキーを持つ。署名付き URL は表示のたびに作る)
- sort\_order に、選んだ順番(0〜3)を入れる。表示はこの順
- 投稿を削除すると、post\_images の行も ON DELETE CASCADE で消える

**S3 バケットの設定**

| 項目 | 設定 |
| --- | --- |
| パブリックアクセス | すべてブロック(非公開) |
| CORS | アプリのオリジンからの PUT と GET を許可する |
| サーバー側暗号化 | S3 標準の暗号化(SSE-S3)を有効にする |
| アクセス権限 | EC2 に付ける IAM ロールに、このバケットだけの PutObject / GetObject / DeleteObject を与える |

**削除**

1. 投稿を削除したときは、DB の削除をコミットした後で、その image\_key のオブジェクトを S3 から消す(一括削除)
2. S3 の削除に失敗しても、ユーザーには成功を返し、キーをログに残す
3. アイコンを変更したときも、古いアイコンのオブジェクトを消す

## 5. エラーと境界値

- 4 枚ちょうどは可、5 枚目を選んだときは選択できない。サーバーも 5 枚目を拒否する(400)
- ちょうど 5MB は可、5MB を 1 バイトでも超えると拒否する
- 拡張子だけ .jpg にした別の形式のファイル: マジックナンバーの確認で拒否する(400)
- S3 への PUT に失敗したとき: 画像ごとにエラーを出し、投稿は送信しない。再試行できるようにする
- 署名付き URL の有効期限切れで PUT が失敗したとき: URL を取り直して 1 回だけ再試行する
- 画像のアップロード後に投稿しなかったとき: S3 に使われない画像が残る(未決事項)
- 表示中に URL の有効期限が切れたとき: 画像が割れるので、一覧を再取得すると新しい URL になる

## 6. 受け入れ条件

- [ ] JPEG、PNG、WebP を 4 枚まで投稿でき、タイムラインにサムネイルで出る
- [ ] 5 枚目・5MB 超・GIF などは、画面とサーバーの両方で拒否される
- [ ] 画像のバイト列が Spring Boot を通らず、S3 へ直接送られる
- [ ] S3 のバケットに直接アクセスしても、署名の無い URL では画像が見られない
- [ ] 他人の imageKey を自分の投稿に使おうとすると 400 になる
- [ ] 画像付きの投稿を削除すると、S3 のオブジェクトも消える
- [ ] アイコンを変更すると、S-05 と投稿カードのアイコンが変わる

## 7. 未決事項

- [ ] 使われなかったアップロード画像の掃除(S3 のライフサイクルルールで一定期間後に消す案と、投稿確定時に別の場所へ移す案)
- [ ] 署名付き GET をやめて CloudFront で配信するか
- [ ] 画像の縮小(サムネイル生成)をするか
- [ ] アイコンのサイズ上限を投稿画像と分けるか
