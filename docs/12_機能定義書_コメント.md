# RaiseTimeLine 機能定義書: コメント

Oct 20, 2026 · @tamura

## 1. 概要と権限

投稿に対して、投稿者本人を含むすべてのログイン済みユーザーがコメントできる機能です。第三者のコメントが付くことを前提に、コメント数を投稿ごとに表示します。コメントへのコメント(スレッド)は作りません。

| 対象機能 | 画面 | 説明 |
| --- | --- | --- |
| F-09 コメント投稿 | S-04 | 280 文字までのテキストをコメントとして送る |
| F-10 コメント一覧表示 | S-04 | その投稿へのコメントを古い順に表示する |
| F-11 コメント数表示 | S-03, S-04, S-05 | 投稿カードにコメントの総数を表示する |
| F-12 コメント削除 | S-04 | 自分のコメントだけ削除できる |

| 操作 | 未ログイン | ログイン済み(コメントした本人) | ログイン済み(第三者) |
| --- | --- | --- | --- |
| コメントとコメント数の閲覧 | 不可(ログインが必要) | 可 | 可 |
| コメントする | 不可 | 可 | 可 |
| コメントを削除する | 不可 | 可 | 不可 |

## 2. 入力項目と処理の流れ

| 項目 | 必須 | ルール | エラー文言(仮) |
| --- | --- | --- | --- |
| 本文 | 必須 | 1〜280 文字(コードポイント数)。前後の空白を取り除く。空白や改行だけは不可。画像は付けられない | コメントを入力してください / 280 文字以内で入力してください |

**コメント投稿(F-09)**

1. S-04 の入力欄に本文を入れ、送信を押す(送信中はボタンを無効にする)
2. POST /api/posts/{id}/comments を呼ぶ
3. サーバーが、投稿の存在と本文を検証し、comments に保存する
4. 201 と、作成したコメント・最新のコメント数を返す
5. 画面は一覧の末尾に追加し、コメント数を返ってきた値に更新する。入力欄は空に戻す

**コメント一覧表示(F-10)と件数表示(F-11)**

1. S-04 を開くと、投稿と同時に GET /api/posts/{id}/comments で先頭 20 件を古い順に取得する
2. 一覧の末尾が画面に近づくと、nextCursor を渡して続きを自動で取得し、末尾に足す(無限スクロール。「もっと見る」ボタンは置かない)。nextCursor が null になったら読み込みを止める。取得に失敗したときは、末尾に再試行ボタンを出す
3. コメント数は投稿データ(PostDto の commentCount)から表示する。一覧の件数を数えて表示しない(続きを読んでいないとずれるため)

**コメント削除(F-12)**

1. 自分のコメントにだけ「削除」を出し、押すと確認ダイアログを出す
2. DELETE /api/comments/{id} を呼ぶ
3. サーバーが、ログイン中のユーザーがそのコメントの投稿者かを確認して削除する
4. 画面は一覧から消し、コメント数を返ってきた値に更新する

## 3. API

パスは仮です。

| メソッド | パス | 認証 | リクエスト | 成功 | 失敗 |
| --- | --- | --- | --- | --- | --- |
| GET | /api/posts/{id}/comments | 必要 | cursor, limit(既定 20、最大 50) | 200 + { items: CommentDto\[\], nextCursor } | 404 投稿が無い |
| POST | /api/posts/{id}/comments | 必要 | body | 201 + { comment: CommentDto, commentCount } | 400 検証エラー / 401 / 404 投稿が無い |
| DELETE | /api/comments/{id} | 必要 | なし | 200 + { commentCount } | 401 / 403 他人のコメント / 404 |

**CommentDto**

| フィールド | 型 | 説明 |
| --- | --- | --- |
| id | number | コメント ID |
| postId | number | コメント先の投稿 |
| body | string | 本文 |
| createdAt | string(ISO 8601) | コメント日時 |
| author | { id, handle, displayName, avatarKey } | コメントした人 |
| mine | boolean | ログイン中のユーザー自身のコメントか(削除ボタンを出すため) |

## 4. DB

使うテーブルは comments(列は要件定義書の「7. データモデル」を参照)です。一覧は古い順のカーソル方式です。

```sql
CREATE INDEX idx_comments_post_created ON comments (post_id, created_at, id);

SELECT c.*
FROM comments c
WHERE c.post_id = :postId
  AND (c.created_at, c.id) > (:cursorCreatedAt, :cursorId)
ORDER BY c.created_at, c.id
LIMIT 21;
```

**コメント数の求め方**

コメント数は列として持たず、表示のたびに数えます。一覧では 20 件分を 1 回のクエリでまとめて数えます。

```sql
SELECT post_id, COUNT(*) AS comment_count
FROM comments
WHERE post_id IN (:postIds)
GROUP BY post_id;
```

コメントが 0 件の投稿は結果に出ないので、アプリ側で 0 を補います。

**外部キー**

- post\_id: posts.id を参照し、ON DELETE CASCADE(投稿を消すとコメントも消える)
- user\_id: users.id を参照(ユーザー削除は今回の対象外)

## 5. エラーと境界値

- 本文がちょうど 280 文字は可、281 文字は 400
- コメントを書いている間に投稿が削除されたとき: 送信すると 404。「投稿が見つかりません」と表示し、S-03 へ戻す
- 他人のコメントを DELETE したとき: 403。サーバーで必ず拒否する
- 第三者が同時にコメントしているとき: コメント数は、自分の操作のレスポンスの値で更新する。他人のコメントは再読み込みで反映される。自動更新はしない
- コメントが 0 件のとき: 「まだコメントがありません」と表示する

## 6. 受け入れ条件

- [ ] 投稿者以外のユーザーでも、投稿にコメントできる
- [ ] コメントは古い順に並び、コメントした人の表示名と @ハンドル、時刻が出る
- [ ] コメントすると、S-03 と S-04 のコメント数が 1 増える
- [ ] 自分のコメントだけに削除ボタンが出て、削除するとコメント数が 1 減る
- [ ] 投稿を削除すると、そのコメントも消える
- [ ] 21 件以上あるときは、末尾までスクロールすると重複なく続きが自動で出る(無限スクロール)
- [ ] 未ログインでコメントを送ろうとすると、S-01 へ移動する
