# RaiseTimeLine 機能定義書: ユーザー検索

Oct 20, 2026 · @tamura

## 1. 概要と検索の仕様

気になるユーザーを @ハンドルと表示名の部分一致で探し、結果の行からその場でフォローできる機能です。フォローの入口になるため、フォローの仕様は「フォロー」の機能定義書を参照してください。

| 対象機能 | 画面 | 説明 |
| --- | --- | --- |
| F-21 ユーザー検索 | S-07 | 検索ボックスに入力して、ユーザーの一覧を出す |
| F-22 検索結果からフォロー | S-07 | 結果の各行にフォロー状態とフォロー・解除ボタンを出す |

**検索の仕様**

| 項目 | 決めたこと |
| --- | --- |
| 検索対象 | ユーザーハンドル(handle)と表示名(display\_name)。メールアドレスと自己紹介は対象にしない |
| 一致のしかた | 部分一致(検索語が含まれればよい)。大文字と小文字を区別しない |
| 並び順 | 先頭が一致するユーザーを上に、その中ではハンドルの昇順 |
| 件数 | 1 回 20 件。末尾までスクロールすると続きを自動で読み込む(無限スクロール) |
| 自分自身 | 結果に含める。フォローボタンは出さない |
| 複数の語 | 空白で区切った語を AND 条件にすることはしない(空白を含む文字列としてそのまま探す) |

| 操作 | 未ログイン | ログイン済み |
| --- | --- | --- |
| ユーザーを検索する | 不可(現在の実装。S-07 はログイン必須) | 可 |
| 結果からフォロー・解除する | 不可 | 可 |

## 2. 入力と処理の流れ

| 項目 | 必須 | ルール | エラー文言(仮) |
| --- | --- | --- | --- |
| 検索語(q) | 必須 | 1〜50 文字。前後の空白を取り除く。先頭の @ は取り除く(@taro でも taro でも同じ結果) | 検索語を入力してください / 50 文字以内で入力してください |

**処理の流れ(F-21)**

1. S-07 で入力する。入力を止めて 300ms 後、または Enter で検索を開始する
2. GET /api/search/users?q=...&cursor=... を呼ぶ。前のリクエストがまだ終わっていないときは取り消す
3. サーバーが文字を整えて(空白・@、LIKE の特殊文字のエスケープ)検索し、ログイン中のユーザーがフォロー済みかを合わせて返す
4. 画面は一覧を置き換える。最後に送ったリクエストの結果だけを表示する(遅れて届いた古い結果で上書きしない)
5. 0 件のときは「見つかりませんでした」を表示する

**結果からフォロー(F-22)**

フォロー・解除の処理は「フォロー」の機能定義書と同じです。押した行だけボタンの表示を切り替え、一覧全体は再取得しません(並び順も変わりません)。

## 3. API

パスは仮です。ハンドルが `search` のユーザーの `/api/users/{handle}` と衝突しないよう、`/api/users/` の下には置かず `/api/search/users` にしています。結果の 1 行は、「フォロー」の機能定義書の UserSummaryDto と同じです。

| メソッド | パス | 認証 | リクエスト | 成功 | 失敗 |
| --- | --- | --- | --- | --- | --- |
| GET | /api/search/users | 必要 | q, cursor, limit(既定 20、最大 50) | 200 + { items: UserSummaryDto\[\], nextCursor } | 400 q が空、または 50 文字超 / 401 |

並び順が「先頭一致 → ハンドル」で、時刻では並びないため、cursor は「何件目か(OFFSET)」を表す不透明な文字列にします。ページをめくる間に新しいユーザーが登録されると、一覧の順番がずれることがありますが、学習用の規模では許容します。

## 4. DB

部分一致(「%検索語%」)は、通常の B-tree インデックスが効きません。PostgreSQL の pg\_trgm(3 文字の塊で索引する拡張)と GIN インデックスを使います。

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX idx_users_handle_trgm       ON users USING gin (handle       gin_trgm_ops);
CREATE INDEX idx_users_display_name_trgm ON users USING gin (display_name gin_trgm_ops);

SELECT u.id, u.handle, u.display_name, u.bio, u.avatar_key
FROM users u
WHERE u.handle       ILIKE :contains ESCAPE '\'
   OR u.display_name ILIKE :contains ESCAPE '\'
ORDER BY (u.handle       ILIKE :prefix ESCAPE '\'
       OR u.display_name ILIKE :prefix ESCAPE '\') DESC,
         u.handle
LIMIT :limit OFFSET :offset;   -- :limit は表示件数 + 1

-- :contains は '%' || エスケープ済みの検索語 || '%'、:prefix は エスケープ済みの検索語 || '%'(どちらもプレースホルダーで渡す)

-- ログイン中のユーザーが、結果の人をフォロー済みか(1 回のクエリ。フォロー一覧と同じ)
SELECT followee_id FROM follows
WHERE follower_id = :me AND followee_id IN (:userIds);
```

**エスケープ**

検索語に `%` や `_` や `\` が含まれると、ワイルドカードやエスケープ文字として動いてしまいます。DB に渡す前に、`\` → `\\`、`%` → `\%`、`_` → `\_` に置き換えます(エスケープ文字は `ESCAPE '\'` で指定)。検索語はプレースホルダー(`:contains` と `:prefix`)で渡し、SQL 文字列に直接組み立てません。

**性能の注意**

- 検索語が 1〜2 文字のときは trigram の索引が効かず、全件を読む。学習用のユーザー数では問題にならないので、最低文字数を設けない
- 実装後に EXPLAIN で、索引が使われることを確かめる
- RDS でも pg\_trgm は標準で使える(CREATE EXTENSION を実行する権限が必要)

## 5. エラーと境界値

- q が空・空白だけ・@ だけ: 400(画面では検索を送らない)
- q がちょうど 50 文字は可、51 文字は 400
- % や \_ を含む検索語: リテラル文字として探す(全件がヒットしない)
- 大文字・小文字・全角半角: 英字の大小は区別しない。全角・半角の正規化は今回はしない
- 検索中にフォローした相手がいるとき: ボタンの表示だけ変える

## 6. 受け入れ条件

- [ ] 「taro」で検索すると、ハンドルまたは表示名に taro を含むユーザーが出る(大文字小文字は問わない)
- [ ] 「@taro」と「taro」で結果が同じになる
- [ ] 先頭が一致するユーザーが上に並ぶ
- [ ] 「%」を検索しても全ユーザーが出ない
- [ ] メールアドレスや自己紹介の文字ではヒットしない
- [ ] 結果の行からその場でフォロー・解除でき、自分の行にはボタンが出ない
- [ ] 素早く入力しても、最後の入力の結果だけが表示される
- [ ] 21 人以上ヒットするときは、末尾までスクロールすると続きが自動で出る(無限スクロール)
