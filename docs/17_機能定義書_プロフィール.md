# RaiseTimeLine 機能定義書: プロフィール

Oct 23, 2026 · @tamura

## 1. 概要と権限

ユーザーのプロフィール(アイコン、表示名、自己紹介、フォロー数・フォロワー数、投稿一覧)を表示し、本人が表示名・自己紹介・アイコンを編集できるようにする機能です。プロフィールに関する仕様はこの文書にまとめます。

| 対象機能 | 画面 | 説明 |
| --- | --- | --- |
| F-08 ユーザープロフィールページ | S-05 プロフィール | 特定ユーザーのプロフィールと投稿一覧を見る |
| F-03 プロフィール編集 | S-06 プロフィール編集 | 表示名と自己紹介を変更する |
| F-17 アイコン画像 | S-06 プロフィール編集 | プロフィール用の画像を 1 枚設定する |

フォロー数・フォロワー数の表示(F-19)とフォローボタン(F-18)は S-05 にありますが、仕様は「フォロー」の機能定義書にあります。画像のアップロード処理は「画像投稿」の機能定義書にあります。

**ルール**

- 編集できるのは表示名・自己紹介・アイコンの 3 つだけ。ハンドル(@id)とメールアドレスは、この画面では変更しない
- 編集は本人だけ。他人のプロフィールを書き換えるリクエストはサーバー側で拒否する
- 編集の対象は常に「ログイン中のユーザー自身」で、リクエストにユーザー ID やハンドルは含めない(PUT /api/users/me)

| 操作 | 未ログイン | ログイン済み(本人) | ログイン済み(第三者) |
| --- | --- | --- | --- |
| プロフィールの閲覧 | 不可(現在の実装方針。S-05 はログイン必須) | 可 | 可 |
| プロフィールを編集する | 不可 | 可 | 不可 |
| フォロー・解除する | 不可 | — (自分自身は不可) | 可 |

## 2. 画面の振る舞い

**S-05 プロフィール(/users/:handle)**

- 上部にアイコン、表示名、@ハンドル、自己紹介、フォロー数・フォロワー数を表示する。自己紹介が未設定のときは行ごと出さない
- アイコンが未設定のときは、表示名の頭文字を入れた既定のアイコンを表示する(仮)
- 本人のプロフィールには「プロフィールを編集」ボタンを出し、押すと S-06 へ移動する。他人のプロフィールにはフォロー / フォロー中ボタンを出す
- 下部にそのユーザーの投稿一覧を新しい順に表示する。カードの共通仕様と無限スクロール(20 件ずつ)は「タイムライン・投稿」の機能定義書と同じ
- 存在しないハンドルを開いたときは、「ユーザーが見つかりません」を表示する
- 投稿が 0 件のときは、「まだ投稿がありません」を表示する(本人のときは、投稿を促す文言にするかは未決)

**S-06 プロフィール編集(/settings/profile)**

- 表示名(1 行入力)、自己紹介(複数行入力)、アイコン画像(選択とプレビュー)、保存ボタン、キャンセルを置く
- 自己紹介の入力欄の近くに「残り文字数」を表示する。160 文字を超える、または表示名が空のときは保存ボタンを無効にする
- アイコンを選ぶと、その場でプレビューを表示する。S3 へのアップロードは保存ボタンを押したときに行う(選んだだけで S3 に画像を残さないため)
- アイコンを未設定に戻す「画像を削除」ボタンを置く(仮)
- キャンセルを押すと、入力を捨てて S-05 へ戻る

## 3. 入力項目と検証

検証は画面(React)とサーバー(Spring Boot)の両方で行います。サーバー側を正とします。表示名と自己紹介のルールは、「認証」の機能定義書と同じです。

| 項目 | 必須 | ルール | エラー文言(仮) |
| --- | --- | --- | --- |
| 表示名 | 必須 | 1〜50 文字。前後の空白を取り除く。空白だけは不可 | 表示名は 1〜50 文字で入力してください |
| 自己紹介 | 任意 | 160 文字以内(コードポイント数で数える)。途中の改行は保持する。空文字は未設定として保存する | 自己紹介は 160 文字以内で入力してください |
| アイコン画像 | 任意 | 1 枚。JPEG / PNG / WebP、5MB まで。詳細は「画像投稿」の機能定義書を参照 | 画像は 1 枚 5MB 以下にしてください / JPEG、PNG、WebP の画像を選んでください |

## 4. 処理の流れ

**プロフィールの表示(F-08)**

1. S-05 を開くと、GET /api/users/{handle} でプロフィールを取得する
2. 続けて GET /api/users/{handle}/posts で投稿を先頭から 20 件取得する(2 つの呼び出しは並行して行う)
3. 末尾が画面に近づいたら、nextCursor を渡して続きを取得する(無限スクロール)
4. 404 のときは「ユーザーが見つかりません」を表示する

**プロフィールの編集(F-03, F-17)**

1. S-06 を開くと GET /api/auth/me で現在の値を取得し、フォームに入れる
2. アイコンを変更したときだけ、POST /api/images/upload-url(purpose=avatar)で署名付き URL を得て、画像を S3 に直接 PUT し、imageKey を得る
3. 保存で PUT /api/users/me を呼ぶ。サーバーが再検証し、対象はログイン中の本人の行だけを更新する
4. サーバーは avatarKey が、ログイン中のユーザー自身のキー(avatars/{userId}/...)であり、S3 に存在することを確認する(「画像投稿」の画像の確認と同じ)
5. アイコンを変更した場合は、DB の更新をコミットした後で、古いアイコンのオブジェクトを S3 から消す。失敗しても成功を返し、キーをログに残す
6. 200 を受けたら、画面が保持しているログイン中のユーザーの情報を更新し(ヘッダーのアイコンや表示名にすぐ反映する)、S-05 へ戻る

## 5. API

API の正は、コードから自動生成する API 仕様書(Swagger UI の `/api/swagger-ui.html`、[docs/api/openapi.json](./api/openapi.json))です。この表は読みやすくまとめたもので、食い違う場合は仕様書を優先します。エラーはすべて { "code": "...", "message": "..." } の形式で、入力検証エラー(400)には項目ごとの `fieldErrors` を付けます(「認証」の機能定義書と同じ)。

| メソッド | パス | 認証 | リクエスト | 成功 | 失敗 |
| --- | --- | --- | --- | --- | --- |
| GET | /api/users/{handle} | 必要(仮) | なし | 200 + UserProfileDto | 401 / 404 |
| GET | /api/users/{handle}/posts | 必要(仮) | cursor, limit | 200 + { items: PostDto\[\], nextCursor } | 401 / 404 |
| GET | /api/auth/me | 必要 | なし | 200 + ログイン中のユーザー(bio, avatarUrl を含む) | 401 |
| PUT | /api/users/me | 必要 | displayName, bio, avatarKey(新しいアイコンのキー。任意)、removeAvatar(true でアイコンを削除。任意) | 200 + 更新後のユーザー | 400 検証エラー / 401 |

ハンドルは大文字小文字を区別せず一致させます。

**UserProfileDto(GET /api/users/{handle})**

| フィールド | 型 | 説明 |
| --- | --- | --- |
| id, handle, displayName | — | ユーザーの基本情報 |
| bio | string / null | 自己紹介。未設定は null |
| avatarUrl | string / null | アイコンの署名付き GET URL。未設定は null(有効期限と URL の作り方は「画像投稿」を参照)。同じ URL を、有効期間の半分(30 分)使い回す(ブラウザのキャッシュが効き、S3 へのリクエストも減る) |
| followingCount, followerCount | number | フォロー数、フォロワー数 |
| followedByMe | boolean | ログイン中のユーザーがフォロー済みか |
| isMe | boolean | ログイン中のユーザー自身のプロフィールか(編集ボタンとフォローボタンの出し分けに使う) |

メールアドレスは本人以外に返しません(GET /api/auth/me の本人向けレスポンスだけに含める)。

**PUT /api/users/me のリクエスト**

| フィールド | 型 | 説明 |
| --- | --- | --- |
| displayName | string | 必須 |
| bio | string / null | 空文字または null は「未設定」として保存する |
| avatarKey | string | 新しいアイコンのキー(S3 へアップロード済みの画像)。無ければ(省略・null)アイコンは変えない |
| removeAvatar | boolean | true でアイコンを削除する(未設定に戻す)。avatarKey とは同時に指定できない(400)。無ければ削除しない |

## 6. DB

使うテーブルは users です(列は要件定義書の「7. データモデル」を参照)。この機能で更新する列は display\_name、bio、avatar\_key だけです(users に更新日時の列は無いので、追加しません)。

```sql
-- プロフィール更新(本人の行だけ)
UPDATE users
SET display_name = :displayName,
    bio = :bio,
    avatar_key = :avatarKey
WHERE id = :me;

-- プロフィール表示(ハンドルは大文字小文字を区別しない)
SELECT id, handle, display_name, bio, avatar_key
FROM users
WHERE lower(handle) = lower(:handle);
```

アイコンを変えないとき(avatarKey も removeAvatar も無い)は、avatar\_key を SET に含めません。SQL は MyBatis の XML に書き、この動的な部分は `<set>` と `<if>` で表します。

## 7. エラーと境界値

- 表示名が前後の空白だけ: 取り除いた結果が空になるので 400
- 表示名がちょうど 50 文字は可、51 文字は 400。自己紹介がちょうど 160 文字は可、161 文字は 400。絵文字は 1 文字として数える
- 他人の avatarKey(avatars/{他人の ID}/...)を指定した: 400。S3 にキーが存在しない場合も 400
- 画像のアップロードに成功し、PUT /api/users/me に失敗したとき: S3 に使われない画像が残る(「画像投稿」の未決事項と同じ扱い)。画面は入力を保持し、再試行できるようにする
- 保存ボタンの連打: 送信中は保存ボタンを無効にする。同じ内容の PUT は何度送っても結果が同じ(冪等)
- 保存が成功しても古いアイコンの削除に失敗したとき: ユーザーには成功を返し、キーをログに残す
- 別の端末で同時に編集したとき: 後から保存した内容で上書きする(競合の検知はしない)
- ログイン中にアクセストークンが切れたとき: 401 を受けたらリフレッシュして 1 回だけ再試行する(「認証」の機能定義書と同じ)
