# RaiseTimeLine 機能定義書: いいね

Oct 20, 2026 · @tamura

## 1. 概要と権限

投稿にいいねを付け、取り消す機能です。第三者の投稿にも付けられ、投稿ごとにいいね数を表示します。同じユーザーが同じ投稿に付けられるのは 1 回だけです。

| 対象機能 | 画面 | 説明 |
| --- | --- | --- |
| F-13 いいね付与 / 取消 | S-03, S-04, S-05 | ♡ を押すと付け、もう一度押すと外れる |
| F-14 いいね数表示 | S-03, S-04, S-05 | いいねの総数と、自分が付けているかを表示する |

| 操作 | 未ログイン | ログイン済み(投稿者本人) | ログイン済み(第三者) |
| --- | --- | --- | --- |
| いいね数の閲覧 | 可(仮) | 可 | 可 |
| いいねを付ける・外す | 不可 | 可(仮) | 可 |

**画面の振る舞い**

- 未いいねは ♡、いいね済みは塗りつぶしの♡。横にいいね数を並べる
- 押した直後に画面を先に更新し(楽観的更新)、サーバーの結果でいいね数を上書きする。失敗したときは元に戻して、短いエラーを出す
- ♡ を押しても画面遷移しない。カード本体のクリックとは別のボタンとして扱う
- 未ログインで押すと S-01 へ移動し、ログイン後に元の画面へ戻す
- インプレッション数やリツイートと混同しないよう、いいね数のみを表示する

## 2. API と処理の流れ

「付ける」を PUT、「外す」を DELETE にします。どちらも同じリクエストを何回送っても結果が同じ(冪等)なので、二重クリックや通信の再試行でも件数がずれません。API の正は、コードから自動生成する API 仕様書(Swagger UI の `/api/swagger-ui.html`、[docs/api/openapi.json](./api/openapi.json))です。この表は読みやすくまとめたもので、食い違う場合は仕様書を優先します。

| メソッド | パス | 認証 | リクエスト | 成功 | 失敗 |
| --- | --- | --- | --- | --- | --- |
| PUT | /api/posts/{id}/like | 必要 | なし | 200 + { likeCount, likedByMe: true } | 401 / 404 投稿が無い |
| DELETE | /api/posts/{id}/like | 必要 | なし | 200 + { likeCount, likedByMe: false } | 401 / 404 投稿が無い |

いいね数と likedByMe は、一覧・詳細の API(PostDto)で返します(「タイムライン・投稿」の機能定義書を参照)。

**付与(F-13)**

1. ♡ を押し、画面を先に♥ と +1 にする
2. PUT /api/posts/{id}/like を呼ぶ
3. サーバーが投稿の存在を確認し、likes に行を入れる(すでにあれば何もしない)
4. サーバーが数えた最新のいいね数を返し、画面はその値で上書きする

**取消(F-13)**

1. ♥ を押し、画面を先に ♡ と −1 にする
2. DELETE /api/posts/{id}/like を呼ぶ
3. サーバーが likes の行を消す(無ければ何もしない)
4. 最新のいいね数を返し、画面はその値で上書きする

## 3. DB

使うテーブルは likes です(列は要件定義書の「7. データモデル」を参照)。(user\_id, post\_id) の複合主キーにより、同時に 2 回押されても DB が二重登録を拒否します。

```sql
-- 付与(すでにあれば何もしない)
INSERT INTO likes (user_id, post_id, created_at)
VALUES (:me, :postId, now())
ON CONFLICT (user_id, post_id) DO NOTHING;

-- 取消
DELETE FROM likes WHERE user_id = :me AND post_id = :postId;

-- 件数
SELECT COUNT(*) FROM likes WHERE post_id = :postId;
```

一覧では、表示する 20 件分をまとめて 2 回のクエリで取ります。

```sql
SELECT post_id, COUNT(*) AS like_count
FROM likes WHERE post_id IN (:postIds) GROUP BY post_id;

SELECT post_id FROM likes
WHERE user_id = :me AND post_id IN (:postIds);
```

付与と件数の取得は同じトランザクションにします。likes にも post\_id を先頭にしたインデックス(post\_id, user\_id)を張り、投稿ごとの件数を数えるクエリを速くします。

## 4. エラーと境界値

- すでにいいね済みの投稿に PUT: エラーにせず 200 を返し、件数も増やさない
- いいねしていない投稿に DELETE: エラーにせず 200 を返す
- 削除済みの投稿にいいね: 404。画面はカードを一覧から消す
- ネットワークエラー: 楽観的に変えた表示を元に戻す
- ♡ を高速で連打: 最後に送ったリクエストの結果を正とする(古い応答で上書きしない)

## 5. 受け入れ条件

- [ ] 第三者の投稿にいいねでき、投稿のいいね数が 1 増える
- [ ] もう一度押すと取り消され、いいね数が 1 減る
- [ ] 同じユーザーが同じ投稿に 2 つ以上いいねを付けられない(API を直接 2 回呼んでも)
- [ ] 2 人が同時にいいねしても、いいね数がずれない
- [ ] リロードしても、自分がいいね済みの投稿は♥ のまま
- [ ] 投稿を削除すると、そのいいねも消える
- [ ] 未ログインで押すと S-01 へ移動する
