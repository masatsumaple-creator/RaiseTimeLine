# RaiseTimeLine 機能定義書: タイムライン・投稿

Oct 20, 2026 · @tamura

## 1. 概要と権限

投稿を作成・削除し、タイムラインとプロフィールで一覧表示する機能です。数字はいいね数とコメント数だけを出し、インプレッション数とリツイートは扱いません。

| 対象機能 | 画面 | 説明 |
| --- | --- | --- |
| F-04 タイムライン表示 | S-03 | 「フォロー中」「全体」の2タブで、投稿を新しい順に表示する |
| F-05 投稿作成 | S-03 | 本文(280 文字まで)と画像で投稿する |
| F-06 投稿削除 | S-03, S-04, S-05 | 自分の投稿だけ削除できる |
| F-07 続きの読み込み | S-03, S-05 | 20 件ずつ読み込む |
| F-08 ユーザープロフィールページ | S-05 | プロフィールと、その人の投稿一覧を見る |

**タブの動き**

| タブ | 表示する投稿 | 既定 |
| --- | --- | --- |
| フォロー中 | 自分と、フォローしているユーザーの投稿 | ✓ |
| 全体 | すべてのユーザーの投稿 |  |

フォロー中が 0 人で、自分の投稿も無いときは、「ユーザーを探してフォローしよう」と案内し、「全体」タブへの切替リンクを出します。選んだタブはブラウザに覚えさせることもできますが、今回は毎回「フォロー中」から始めます。

**権限**

| 操作 | 未ログイン | ログイン済み(本人) | ログイン済み(第三者) |
| --- | --- | --- | --- |
| タイムライン・プロフィールの閲覧 | 可(仮) | 可 | 可 |
| 「フォロー中」タブ | 不可 | 可 | — |
| 投稿する | 不可 | 可 | — |
| 投稿を削除する | 不可 | 可 | 不可 |

## 2. 入力項目と処理の流れ

| 項目 | 必須 | ルール | エラー文言(仮) |
| --- | --- | --- | --- |
| 本文 | 画像が無いときは必須 | 280 文字以内(コードポイント数)。前後の空白を取り除く。空白や改行だけは不可。途中の改行は保持する | 本文または画像を入れてください / 280 文字以内で入力してください |
| 画像 | 任意 | 最大 4 枚。詳細は「画像投稿」の機能定義書を参照 | 画像は 4 枚までです |

画面には「残り文字数」を表示し、280 文字を超えると投稿ボタンを無効にします。

**タイムライン表示(F-04, F-07)**

1. S-03 を開くと、tab=following で先頭 20 件を取得する
2. タブを切り替えると、tab=all で取り直す(カーソルはリセット)
3. 「もっと見る」で、直前のレスポンスの nextCursor を渡して続きを 20 件取得する
4. nextCursor が null になったら「もっと見る」を消す

**投稿作成(F-05)**

1. 画面で文字数を検証し、画像があれば先に S3 へアップロードして imageKeys を得る(「画像投稿」参照)
2. POST /api/posts を呼ぶ
3. サーバーが再検証し、posts と post\_images を同じトランザクションで保存する
4. 201 と作成した投稿を返す。画面は一覧の先頭にその投稿を足す(いいね数 0、コメント数 0)

**投稿削除(F-06)**

1. カードの「削除」を押すと確認ダイアログを出す
2. DELETE /api/posts/{id} を呼ぶ
3. サーバーが「ログイン中のユーザーの投稿か」を確認し、コメント・いいね・画像の行ごと削除する
4. 画面は一覧からそのカードを消す(投稿詳画面で削除したときは S-03 へ)

## 3. API

パスは仮です。一覧系の API は共通で、cursor(続きの位置)と limit(既定 20、最大 50)を受け、「{ items, nextCursor }」を返します。

| メソッド | パス | 認証 | リクエスト | 成功 | 失敗 |
| --- | --- | --- | --- | --- | --- |
| GET | /api/timeline | 必要(tab=following)/ 仮で不要(tab=all) | tab(following を既定とする / all)、cursor, limit | 200 + { items: PostDto\[\], nextCursor } | 400 tab が不正 / 401 未ログイン(following) |
| POST | /api/posts | 必要 | body, imageKeys(0〜4) | 201 + PostDto | 400 検証エラー / 401 |
| GET | /api/posts/{id} | 仮で不要 | なし | 200 + PostDto | 404 |
| DELETE | /api/posts/{id} | 必要 | なし | 204 | 401 / 403 他人の投稿 / 404 |
| GET | /api/users/{handle} | 仮で不要 | なし | 200 + プロフィール | 404 |
| GET | /api/users/{handle}/posts | 仮で不要 | cursor, limit | 200 + { items: PostDto\[\], nextCursor } | 404 |

**PostDto(投稿 1 件の形)**

| フィールド | 型 | 説明 |
| --- | --- | --- |
| id | number | 投稿 ID |
| body | string / null | 本文 |
| createdAt | string(ISO 8601) | 投稿日時 |
| author | { id, handle, displayName, avatarUrl } | 投稿者 |
| images | { url, sortOrder }\[\] | 署名付き URL に変換済み(「画像投稿」参照) |
| likeCount | number | いいね数 |
| commentCount | number | コメント数 |
| likedByMe | boolean | 自分がいいね済みか(未ログインは false) |

インプレッション数やリツイート数のフィールドは、PostDto に持たせません。

## 4. DB

一覧は、OFFSET ではなく「最後に見た投稿の (created\_at, id) より前」で続きを取ります(カーソル方式)。新しい投稿が途中で増えても、同じ投稿が二度出たり押し出されたりしません。cursor は (created\_at, id) を Base64 にした不透明な文字列として返します。

```sql
CREATE INDEX idx_posts_created ON posts (created_at DESC, id DESC);
CREATE INDEX idx_posts_user_created ON posts (user_id, created_at DESC, id DESC);

SELECT p.*
FROM posts p
WHERE (p.created_at, p.id) < (:cursorCreatedAt, :cursorId)
  AND ( :tab = 'all'
        OR p.user_id = :me
        OR p.user_id IN (SELECT followee_id FROM follows WHERE follower_id = :me) )
ORDER BY p.created_at DESC, p.id DESC
LIMIT 21;
```

LIMIT は表示件数 + 1 を取ります。余る 1 件があれば続きがあると判断して nextCursor を返し、無ければ null を返します(先頭ページではカーソル条件を外します)。

**N+1 問題を避ける**

- 投稿の 20 件を取った後に、投稿者・画像・いいね数・コメント数・いいね済みを、投稿 ID の一括(IN)でまとめて取る
- いいね数・コメント数は GROUP BY post\_id で、1回のクエリで 20 件分を数える
- 投稿 1 件ごとにクエリを発行しない

**削除時の連動**

posts を削除すると、外部キーの ON DELETE CASCADE で comments・likes・post\_images の行も消えます。S3 の画像ファイルを消すための流れは、「画像投稿」の機能定義書に書きます。

## 5. エラーと境界値

- 本文がちょうど 280 文字は可、1 文字超えは 400。絵文字・日本語は 1 文字と数える(Java では length() ではなく codePointCount を使う)
- 同じ投稿の二重送信: 送信中はボタンを無効化する。サーバー側での重複判定はしない(同じ文面の連投は許す)
- 存在しない投稿やすでに削除された投稿を開いたとき: 404 を返し、「投稿が見つかりません」と表示する
- 他人の投稿を DELETE したとき: 403。画面でボタンを出さないだけではなく、サーバーで必ず拒否する
- どのタブでも 0 件のとき: 空状態の文言を表示する

## 6. 受け入れ条件

- [ ] 「フォロー中」タブには、自分とフォロー先の投稿だけが新しい順に出る
- [ ] 「全体」タブには、フォローしていない人の投稿も出る
- [ ] 280 文字で投稿でき、281 文字では画面とサーバーの両方で拒否される
- [ ] 画像だけの投稿と、文章だけの投稿ができる
- [ ] 各カードにいいね数とコメント数が出ていて、インプレッション数はどこにも出ていない
- [ ] 21 件以上あるときは「もっと見る」で重複なく続きが出る
- [ ] 自分の投稿だけに削除ボタンが出て、削除するとコメント・いいねも消える
- [ ] 他人の投稿を API で直接削除しようとすると 403 になる
