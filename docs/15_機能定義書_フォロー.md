# RaiseTimeLine 機能定義書: フォロー

Oct 20, 2026 · @tamura

## 1. 概要と権限

他のユーザーをフォローして、タイムラインの「フォロー中」タブにその人の投稿を表示する機能です。フォローは一方向で、相手の承認はいりません。フォロー数とフォロワー数は表示しますが、インプレッション数と同様に「数字を競う」要素にしないよう、ランキングや「おすすめユーザー」は作りません。

| 対象機能 | 画面 | 説明 |
| --- | --- | --- |
| F-18 フォロー / 解除 | S-05, S-07, S-08 | 他のユーザーをフォローし、解除できる |
| F-19 フォロー数・フォロワー数表示 | S-05 | プロフィールに、フォローしている人数とされている人数を表示する |
| F-20 フォロー中 / フォロワー一覧 | S-08 | あるユーザーのフォロー先とフォロワーを一覧で見る |

**ルール**

- 1 人が同じ相手をフォローできるのは 1 回だけ
- 自分自身はフォローできない
- フォローすると、その人の過去の投稿も「フォロー中」タブに出る
- フォローを解除すると、「フォロー中」タブからその人の投稿が消える(「全体」タブには残る)

| 操作 | 未ログイン | ログイン済み |
| --- | --- | --- |
| フォロー数・フォロワー数と一覧の閲覧 | 不可(現在の実装。S-05・S-08 はログイン必須) | 可 |
| フォロー・解除する | 不可 | 可(自分自身を除く) |

## 2. 画面の振る舞いと処理の流れ

**画面の振る舞い**

- S-05(他人のプロフィール): フォローしていないときは「フォロー」、しているときは「フォロー中」を表示する。押すと画面を先に更新し、フォロワー数を +1 / −1 する。サーバーの結果で数を上書きする
- S-05(自分のプロフィール): フォローボタンの代わりに編集ボタンを表示する
- フォロー数・フォロワー数を押すと、S-08 をそのタブで開く
- S-08: 行のアイコン・名前を押すと S-05 へ。行の右端のボタンでその場でフォロー・解除する(自分の行にはボタンを出さない。「フォロー中」の一覧で解除しても、その行は一覧に残り、ボタンの表示だけが変わる。一覧は取り直さない)
- 未ログインで押すと S-01 へ移動し、ログイン後に元の画面へ戻す

**フォロー(F-18)**

1. 「フォロー」を押し、画面を先に「フォロー中」にする
2. PUT /api/users/{handle}/follow を呼ぶ
3. サーバーが、相手の存在と、自分自身ではないことを確認して、follows に行を入れる(すでにあれば何もしない)
4. 相手の最新のフォロワー数を返し、画面はその値で上書きする

**解除(F-18)**

1. 「フォロー中」を押し、画面を先に「フォロー」に戻す(誤操作を減らすために確認ダイアログを出すかは未決)
2. DELETE /api/users/{handle}/follow を呼ぶ
3. サーバーが follows の行を消す(無ければ何もしない)
4. 相手の最新のフォロワー数を返し、画面はその値で上書きする

## 3. API

パスは仮です。付ける・外すは、「いいね」と同じく PUT / DELETE の冪等な設計にします。

| メソッド | パス | 認証 | リクエスト | 成功 | 失敗 |
| --- | --- | --- | --- | --- | --- |
| PUT | /api/users/{handle}/follow | 必要 | なし | 200 + { followedByMe: true, followerCount } | 400 自分自身(code は `CANNOT_FOLLOW_SELF`)/ 401 / 404 相手がいない |
| DELETE | /api/users/{handle}/follow | 必要 | なし | 200 + { followedByMe: false, followerCount } | 401 / 404 |
| GET | /api/users/{handle}/following | 必要(仮) | cursor, limit | 200 + { items: UserSummaryDto\[\], nextCursor } | 400 cursor が不正 / 401 / 404 |
| GET | /api/users/{handle}/followers | 必要(仮) | cursor, limit | 200 + { items: UserSummaryDto\[\], nextCursor } | 400 cursor が不正 / 401 / 404 |

**プロフィール(GET /api/users/{handle})に加えるフィールド**(UserProfileDto 全体は「プロフィール」の機能定義書)

| フィールド | 型 | 説明 |
| --- | --- | --- |
| followingCount | number | このユーザーがフォローしている人数 |
| followerCount | number | このユーザーをフォローしている人数 |
| followedByMe | boolean | ログイン中のユーザーがフォロー済みか(未ログインは false) |
| isMe | boolean | ログイン中のユーザー自身のプロフィールか |

**UserSummaryDto(一覧の 1 行、ユーザー検索と共通)**

| フィールド | 型 | 説明 |
| --- | --- | --- |
| id, handle, displayName, avatarUrl | — | ユーザーの表示用情報 |
| bio | string / null | 自己紹介(一覧では 1 行目だけ表示する) |
| followedByMe | boolean | ログイン中のユーザーがフォロー済みか |
| isMe | boolean | 自分自身の行か(ボタンを出さないため) |

## 4. DB

使うテーブルは follows です(列は要件定義書の「7. データモデル」を参照)。複合主キーで二重フォローを、CHECK 制約で自分自身のフォローを DB が拒否します。

```sql
CREATE TABLE follows (
  follower_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  followee_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (follower_id, followee_id),
  CHECK (follower_id <> followee_id)
);
CREATE INDEX idx_follows_followee ON follows (followee_id, created_at DESC, follower_id DESC);
CREATE INDEX idx_follows_follower ON follows (follower_id, created_at DESC, followee_id DESC);

-- フォロー(すでにあれば何もしない)
INSERT INTO follows (follower_id, followee_id)
VALUES (:me, :target)
ON CONFLICT DO NOTHING;

-- 解除
DELETE FROM follows WHERE follower_id = :me AND followee_id = :target;
```

**件数**

フォロー数とフォロワー数は列として持たず、表示のたびに数えます。

```sql
SELECT COUNT(*) FROM follows WHERE follower_id = :target;  -- followingCount
SELECT COUNT(*) FROM follows WHERE followee_id = :target;  -- followerCount
```

**一覧(カーソル方式、新しいフォロー順)**

```sql
-- フォロー中一覧
SELECT u.id, u.handle, u.display_name, u.avatar_key, u.bio
FROM follows f JOIN users u ON u.id = f.followee_id
WHERE f.follower_id = :target
  AND (f.created_at, f.followee_id) < (:cursorCreatedAt, :cursorId)
ORDER BY f.created_at DESC, f.followee_id DESC
LIMIT 21;

-- ログイン中のユーザーが、一覧の 20 人をフォロー済みか(1 回のクエリ)
SELECT followee_id FROM follows
WHERE follower_id = :me AND followee_id IN (:userIds);
```

フォロワー一覧は follower\_id と followee\_id を入れ替えるだけです。

## 5. エラーと境界値

- 自分自身をフォローしようとしたとき(API を直接呼んだ場合): サーバーが先に確認して 400(`CANNOT_FOLLOW_SELF`)。CHECK 制約は、確認をすり抜けたときの二重の防御
- すでにフォロー済みの相手に PUT: エラーにせず 200。フォローしていない相手に DELETEも 200
- 存在しないハンドル: 404
- フォロー中が 0 人・フォロワーが 0 人のとき: 空状態の文言(「まだフォローしていません」「まだフォロワーがいません」)を表示する
- ボタンを連打したとき: 最後に送ったリクエストの結果を正とする
- 相手が同時にフォロワーを増やしているとき: 表示は自分の操作のレスポンスの値で更新し、自動更新はしない

## 6. 受け入れ条件

- [ ] S-05 の「フォロー」を押すと「フォロー中」に変わり、相手のフォロワー数が 1 増える
- [ ] フォローすると、「フォロー中」タブに相手の投稿が出る
- [ ] 解除すると、「フォロー中」タブからその人の投稿が消え、「全体」タブには残る
- [ ] 自分のプロフィールと、一覧の自分の行にはフォローボタンが出ない
- [ ] API を直接呼んでも、自分をフォローできない・同じ相手を 2 重にフォローできない
- [ ] フォロー中・フォロワー一覧が新しいフォロー順に並び、末尾までスクロールすると重複なく続きが自動で出る(無限スクロール)
- [ ] 一覧の各行からその場でフォロー・解除できる
