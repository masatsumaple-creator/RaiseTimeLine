# RaiseTimeLine 機能定義書: 認証

Oct 19, 2026 · @tamura

## 1. 概要と権限

メールとパスワードでユーザーを登録・認証し、プロフィールを編集できるようにする機能です。アイコン画像のアップロードは「画像投稿」の機能定義書にあります。

| 対象機能 | 画面 | 説明 |
| --- | --- | --- |
| F-01 ユーザー登録 | S-02 新規登録 | メール・パスワード・表示名・ハンドルで登録し、そのままログイン状態になる |
| F-02 ログイン / ログアウト | S-01 ログイン | メールとパスワードで認証する。ログアウトでセッションを破棄する |
| F-03 プロフィール編集 | S-06 プロフィール編集 | 表示名と自己紹介を変更する(アイコンは F-17) |

**権限**

- 登録・ログイン画面は未ログインの人向け。ログイン済みで開いたときは S-03 へ移動する
- プロフィール編集は本人だけ。他人のプロフィールを書き換えるリクエストはサーバー側で拒否する

**認証方式(推奨)**

Spring Security のセッション Cookie 方式を推奨します。Cookie は HttpOnly・Secure・SameSite=Lax にし、CSRF トークンをリクエストヘッダーで送ります。ALB と EC2 を 1 台構成で使う前提だと、セッションをサーバーのメモリに持てるためです。JWT 方式は未決事項に残します。

## 2. 入力項目と検証

検証は画面(React)とサーバー(Spring Boot)の両方で行います。サーバー側を正とします。

| 項目 | 対象画面 | 必須 | ルール | エラー文言(仮) |
| --- | --- | --- | --- | --- |
| メールアドレス | S-01, S-02 | 必須 | メール形式。255 文字以内。登録時は大文字小文字を區別せず重複不可 | メールアドレスの形式が正しくありません / このメールアドレスは登録済みです |
| パスワード | S-01, S-02 | 必須 | 8〜64 文字。英字と数字をそれぞれ 1 文字以上含む(登録時のみ) | パスワードは 8〜64 文字で、英字と数字を含めてください |
| ユーザーハンドル | S-02 | 必須 | 3〜30 文字。半角英数字と \_ のみ。先頭の @ は入力不要。大文字小文字を區別せず重複不可 | ユーザーハンドルは半角英数字と \_ の 3〜30 文字で入力してください / このハンドルは使われています |
| 表示名 | S-02, S-06 | 必須 | 1〜50 文字。前後の空白は取り除く | 表示名は 1〜50 文字で入力してください |
| 自己紹介 | S-06 | 任意 | 160 文字以内(コードポイント数で数える) | 自己紹介は 160 文字以内で入力してください |

ログインに失敗したときは、「メールアドレスまたはパスワードが正しくありません」とだけ表示します。どちらが違っていたかは示さないです(メールの登録有無を探されないため)。

## 3. 処理の流れ

**ユーザー登録(F-01)**

1. 画面で入力を検証し、POST /api/auth/signup を呼ぶ
2. サーバーで再度検証する。形式のエラーは 400
3. メールとハンドルの重複を確認する。重複していれば 409
4. パスワードを BCrypt でハッシュ化し、users に保存する
5. そのままログイン状態にして(セッションを作り、Cookie を返す)、201 を返す
6. 画面は S-03 へ移動する

**ログイン(F-02)**

1. 画面でメールとパスワードを送る(POST /api/auth/login)
2. メールで users を探し、BCrypt で照合する
3. 一致しなければ 401(メールとパスワードのどちらが違うかは示さない)
4. 一致すればセッションを作り直し(セッション固定化を防ぐ)、Cookie を返して 200
5. ログイン前に開こうとした画面があればそこへ、なければ S-03 へ移動する

**ログアウト(F-02)**

1. POST /api/auth/logout を呼ぶ
2. サーバーのセッションを破棄し、Cookie を消す
3. 画面は S-01 へ移動する

**プロフィール編集(F-03)**

1. S-06 を開くと GET /api/auth/me で現在の値を取得し、フォームに入れる
2. 保存で PUT /api/users/me を呼ぶ。対象はログイン中の本人の行だけ
3. 成功したら S-05 へ戻る

## 4. API

パスは仮です。エラーはすべて { "code": "...", "message": "..." } の形式で返します。入力検証エラー(400)には、項目ごとのメッセージを入れた `fieldErrors`(項目名 → メッセージ)も付けます。実装済みの code は `VALIDATION_ERROR`(400)・`LOGIN_FAILED`(401)・`UNAUTHORIZED`(401)・`FORBIDDEN`(403、CSRF トークンなし)・`EMAIL_ALREADY_EXISTS` / `HANDLE_ALREADY_EXISTS`(409)です。

| メソッド | パス | 認証 | リクエスト | 成功 | 失敗 |
| --- | --- | --- | --- | --- | --- |
| POST | /api/auth/signup | 不要 | email, password, handle, displayName | 201 + ユーザー(id, handle, displayName) | 400 検証エラー / 409 メールまたはハンドルが重複 |
| POST | /api/auth/login | 不要 | email, password | 200 + ユーザー、Set-Cookie | 400 検証エラー / 401 認証失敗 |
| POST | /api/auth/logout | 必要 | なし | 204 | 401 未ログイン |
| GET | /api/auth/me | 必要 | なし | 200 + ログイン中のユーザー(bio, avatarKey を含む) | 401 未ログイン |
| PUT | /api/users/me | 必要 | displayName, bio, avatarKey(任意) | 200 + 更新後のユーザー | 400 検証エラー / 401 未ログイン |

## 5. DB とセキュリティ

使うテーブルは users です(列は要件定義書の「7. データモデル」を参照)。メールとハンドルの重複を、大文字小文字を區別しない一意インデックスで DB に保証します。

```sql
CREATE UNIQUE INDEX uq_users_email_lower  ON users (lower(email));
CREATE UNIQUE INDEX uq_users_handle_lower ON users (lower(handle));
```

- パスワードは BCrypt(Spring Security の BCryptPasswordEncoder)でハッシュ化し、平文は保存もログ出力もしない
- API のレスポンスに password\_hash を含めない(専用の返却用 DTO を使う)
- ログイン成功時にセッション ID を作り直す(セッション固定化対策)
- 更新系の API では CSRF トークンを必須にする
- 通信は HTTPS(ALB で終端)。HTTP で来たときは HTTPS へリダイレクトする

## 6. エラーと境界値

- 同じメール・ハンドルで同時に登録されたとき: DB の一意制約違反を捕まえて 409 に変換する(事前チェックだけに頑りない)
- セッションが切れた状態で API を呼んだとき: 401 を返し、画面は S-01 へ移動して、ログイン後に元の画面へ戻す
- パスワードの長さ: 64 文字を超える入力は拒否する(BCrypt の入力上限 72 バイトを超えないようにする)
- 自己紹介 160 文字ちょうどは可、161 文字目はエラー。絵文字は 1 文字と数える
- 連続で送信ボタンを押したとき: 送信中はボタンを無効化する

## 7. 受け入れ条件

- [ ] 正しい入力で登録すると、ログイン状態で S-03 が開く
- [ ] 同じメール(大文字小文字違いを含む)での再登録はエラーになる
- [ ] 同じハンドル(大文字小文字違いを含む)での再登録はエラーになる
- [ ] 間違ったパスワードではログインできず、メールとパスワードのどちが違うかがわからない文言になる
- [ ] DB に平文のパスワードが残らない
- [ ] ログアウト後に「戻る」を押しても、ログインが必要な画面の内容が見えない
- [ ] 他人のプロフィールを PUT /api/users/me で変更できない
- [ ] 自己紹介 161 文字は画面とサーバーの両方で拒否される
